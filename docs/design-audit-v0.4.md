# 导师信息收集 Agent —— 设计审计文档

> 版本：v0.4（设计阶段，不含代码）
> 目标用户：一名 CS 大三学生（目标进入 ML/LLM/CV/具身智能/AI4Science 方向实验室）
> 文档目的：冻结需求与边界，暴露设计风险，作为后续开发的"施工图纸"
> v0.4 变更：① M1.5 对比视图改为"全景表 + 深度对比"两档，突破 5 人上限；② M1 卡片新增"职业阶段（青年/中年/资深）"字段及简评；③ M1/M2 检索链路强化"官网 → 个人主页"联动，个人主页为最高优先级信源；④ 申请时间线改造为"院校机会监测 + 倒计时"模块

---

## 1. 项目定位

一句话：**这是一个"申请导向"的导师情报 + 论文伴读 Agent**，不是简单的信息爬虫。

它的核心价值不在"列名单"，而在三件事：
1. **情报可信**——每条信息有出处、有时效、有置信度；
2. **论文讲得懂**——按"目标→背景→流程→概念"的固定框架拆解，匹配用户的知识水位；
3. **形成闭环**——用户读完论文写出思考 → Agent 批改纠偏 → 凝练成有深度的思考段落 → 反向指导"做什么项目能进这个组"。

## 2. 用户画像与知识储备（个性化的依据）

> 此档案是 Agent 所有"解释深度"和"匹配建议"的输入，作为持久化档案维护，随学习进度更新。

### 2.1 知识储备

**已掌握（可以直接用的知识，不用展开讲）：**
- ML/DL 理论：机器学习、深度学习理论，Transformer / RNN / CNN 框架
- 工程实践：HuggingFace Transformers 全流程（chat template → tokenize → 切分 → 微调 → 前后向算 loss → benchmark）；《动手学大模型》各章均跑通（水印、越狱、R-Judge、Agent 两种构建框架、数据整理、CoT、RLHF、PoT）——注意：**停留在"知道+跑过"，不等于"理解深"**
- 系统能力：Shell / 服务器集群训练脚本、Git（快照、switch、checkout）、Vim
- 推理系统入门：算子、kernel 核函数、CPU/GPU 分工、latency 与 throughput、prompt 并行推理、首 token 生成、KV cache 逐层缓存 QKV 预测下一个 token
- 多模态：Qwen2.5-VL 看图问答、CLIP 向量空间与余弦相似度（CPU 级小模型实验）

**项目经历：**
- 熊类行为与个体识别（川农课题组访问学习）：YOLO11 迁移学习，mAP50 0.716→0.803，已交付试运行
- ESM-IF1 蛋白质逆向折叠：完整"设计—评分—评估"流水线，序列恢复率 45.8%，代码开源

**明确的兴趣方向：** ML / LLM / CV / 具身智能 / AI4Science。

### 2.2 解释风格偏好（硬规则）

1. **原理直述，禁用生活比喻。** 解释概念时直接从数学定义、机制、公式推导讲，不使用"像……一样"式的现实类比。
2. **前置概念按需预解释。** 拆解论文时遇到复杂概念，先查用户档案：档案里标记"已掌握"的（如 KV cache、RLHF 流程）一笔带过或仅列名词；档案里没有的，先用一小节把这个概念本身讲清楚（定义、动机、数学形式），再回到论文语境讲它在本文中的用法。
3. **一切阐述挂原文。** 凡是涉及"这篇论文的原理是什么"的陈述、以及 Agent 自己提出的观点（如"我认为这个方法的关键在……"），必须贴出论文原文句子作为佐证，并标注位置（第几节/哪一段）。原文句子与 Agent 的解读分开排版，让用户能清楚区分"作者说的"和"Agent 说的"。

> 注：本条仅约束本 Agent 的输出风格，优先级高于用户的通用教学偏好。

### 2.3 双硬件配置档案（实测）

用户有**两台设备**（一台核显笔记本 + 一台 12GB 显存台式机），Agent 的所有算力相关建议必须区分"在哪台机器上执行"。

**设备 A｜核显笔记本（随身机）**

| 部件 | 规格 |
|---|---|
| GPU | 集成显卡（共享内存作显存） |
| 内存 | 16GB |
| 系统 | Windows 11 64 位 |

**算力红线（设备 A）：**
- ✅ 可行：≤3B 模型 4bit 量化推理（Qwen2.5-3B、Phi-3-mini 级）；数据处理、评测脚本、prompt 工程、API 调用、论文复现的 CPU 环节；CLIP/小 ViT 级视觉实验
- ⚠️ 勉强：7B Q4 推理（速度约 2-4 tok/s，仅用于"跑通看看"，不适合迭代实验）
- ❌ 不可行：任何有实际意义的微调；7B 以上模型；批量实验

**设备 B｜独显台式机（主力训练机）**

| 部件 | 规格 |
|---|---|
| GPU | 独立显卡（12GB 显存） |
| 内存 | 32GB |
| 系统 | Windows 11 64 位 |

**算力红线（设备 B）：**
- ✅ 可行：7-8B 模型 Q4/Q8 量化推理（流畅）；13B Q4 推理；**QLoRA/LoRA 微调 7-8B 级模型**（显存占用约 6-10GB，12GB 刚好够）；全参数微调 ≤1.5B 模型；SD1.5 级扩散模型推理与 LoRA；YOLO 级 CV 训练（已有实践）
- ⚠️ 勉强：7B 全参数微调（12GB 显存极紧，需梯度检查点+极小 batch，实际不推荐）；14B Q4 推理
- ❌ 不可行：13B 以上微调；任何规模的预训练；多卡分布式

**双机分工策略（写进 M4 的项目建议生成规则）：**
- 设备 A（笔记本）：论文阅读与思考写作、数据整理、评测脚本、小规模验证、远程 SSH 到设备 B 的终端
- 设备 B（台式机）：一切训练任务、批量推理、benchmark
- 同步机制：Git 仓库 + 统一 conda 环境定义（环境即代码），保证两台机器实验可复现

**对 Agent 设计的三条推论：**
1. 论文拆解遇到 CUDA/分布式训练细节时，用户是"刚入门"水位，按 2.2 节规则做前置概念解释；
2. 匹配分析必须过滤掉"需要大规模预训练算力"的路径，优先推荐推理优化、数据、评测、小模型、应用层、AI4Science 等单卡可做的切入角度；每个项目建议必须标注**目标设备**（A/B）；
3. 用户已有"费曼学习法"的使用习惯，批改模块要延续"你当老师我追问"的互动感，而不是冷冰冰的判分。

## 3. 功能模块拆解

### M1｜导师列表与画像（情报层）

**输入泛化——支持三级输入：**

| 输入类型 | 示例 | Agent 行为 |
|---|---|---|
| 学校级 | "清华大学有哪些做 LLM 的老师" | 先定位相关学院/研究院（可能跨多个：计算机系、交叉信息院、人工智能学院等），分别枚举师资名单，再按与用户兴趣方向的相关性排序，**相关性低的老师也列出但折叠**，并说明筛选理由 |
| 学院级 | "某某大学某某学院的老师" | 枚举该学院全部师资 → 逐人判定方向相关性 → 排序输出。若该学院不存在/无官网名单/名单为空，如实报告并给出替代检索路径（如查相近学院、用学者库反查） |
| 个人级 | "看看 XXX 老师" | 直接进入 M2 深潜流程 |

**检索链路硬规则（v0.4 新增）——"官网 → 个人主页"两级联动：**
1. 先从学院官网师资页获取名单、职称、官方简介等"框架信息"；
2. **必须顺藤摸瓜找到每位老师的个人主页**（官网教师详情页通常挂有个人主页链接；找不到时通过姓名+机构在搜索引擎/Scholar/GitHub 反查）；
3. **个人主页是最高优先级信源**：研究方向、招生状态、近期动态一律以个人主页为准——学校官网信息常年不更新，个人主页才是老师自己维护的"活信息"；两者冲突时以主页为准并标注冲突；
4. 确实没有个人主页的老师，在卡片上显式标注"无个人主页"，这本身就是一个信号（结合职业阶段判断：资深教授可能没有，青年老师没有主页则略不寻常）。

**关键原则：用户输入不一定准确**——可能记错学院名、可能该院根本没有相关方向的老师。Agent 的职责是"先把这个单位的所有老师摸清楚，再用证据告诉用户哪些值得关注"，而不是顺着用户的假设编一个名单。**查不到就说查不到，绝不凑数。**

**输出：** 结构化导师卡片列表。每张卡片的字段 schema：

| 字段 | 说明 | 来源 | 置信度标注 |
|---|---|---|---|
| 姓名 / 职称 | 教授、副教授、助理教授、研究员等 | 学院官网师资页 | 高 |
| **职业阶段**（v0.4 新增） | 青年 / 中年 / 资深 + **一句话简评** | 履历（学位获得年份、入职年份、职称晋升轨迹） | 中 |
| 研究方向 | 官网自述 + 近3年论文实际主题（两者可能不一致，都要列） | 官网 + **个人主页** + Scholar/arXiv | 高/中 |
| 近期动态 | 最近在做什么项目、开了什么课、有无新实验室 | **个人主页优先**、新闻、组会页 | 中 |
| 招生状态 | 是否明确写"欢迎本科生/实习生/访问学生" | **个人主页** Prospective Students 板块、招生帖 | **必须分级** |
| 联系方式 | 邮箱、主页、GitHub | 官网 + 个人主页 | 高 |
| 代表性论文 | 近3年高引/一作学生为主的论文 | Scholar | 高 |

**"职业阶段"字段细则（v0.4 新增）：**

判定依据（按可用证据，标注来源）：
- **青年**：博士毕业 ≤8 年 / 助理教授、特聘研究员 / 刚建组
- **中年**：副教授到教授中段、组规模稳定、持续产出
- **资深**：教授多年 / 有院士、杰青等头衔 / 组规模大或已转管理岗

一句话简评要给出**对申请者的实际含义**（基于一般规律，标注为"经验性判断"），例如：
- 青年："大概率亲自带人、push 程度高、缺干活的人——本科生机会多，但组的名声和资源可能还在积累期"
- 中年："产出和资源都比较稳定的窗口期"
- 资深："名头响、资源多，但日常指导可能由小导师/博后承担——需要看组里有没有本科生一作的先例"

判定证据不足时标"无法判定"，不允许仅凭照片或感觉猜。

**关键设计点——"欢迎实习"判定三级分类（硬规则，防编造）：**
- 🟢 **明示**：主页/招生帖原文写明欢迎本科生/实习生/访问学生（附原文引用 + 抓取日期）
- 🟡 **推断**：组里有本科生一作论文、历史上有访问学生记录（附证据）
- ⚪ **未知**：没有任何公开信息
- **绝对禁止把 ⚪ 说成 🟢。** 输出时必须带对应图标和证据链。

**风险点：** 官网名单是权威来源，但可能存在新入职未更新、兼职/双聘、荣休等情况。Agent 需标注名单快照的获取日期，并对"名单完整性"本身给出置信说明。

### M1.5｜导师横向对比视图（v0.4 改为两档模式）

一个学校/学院的相关老师远不止 5 位，对比视图分两档：

**档一｜全景对比表（人数不限，通常 10-30 人）**
- 用途：粗筛——"这个学院哪些老师值得我深入了解"
- 列：姓名/职称、职业阶段、方向一句话、活跃度（近24月论文数）、招生信号 🟢🟡⚪、有无个人主页
- 全是**低成本的客观/半客观指标**，可以批量填充；填不了的标"无数据"
- 支持按任意列排序；用户从全景表里勾 2-5 人进入档二

**档二｜深度对比（2-5 人）**
- 用途：终筛——"这几个人我到底主攻谁"
- 完整的七项指标 + 每项的证据链展开 + 证据原文
- 这一档成本高（要逐人查证据），所以限制人数

**七项指标体系（档二使用）：**

| # | 指标 | 计算方式 | 数据来源 | 置信度 |
|---|---|---|---|---|
| 1 | **方向匹配度** | 老师近 24 个月论文主题与用户兴趣方向（ML/LLM/CV/具身/AI4Science）的语义重叠度 + 与用户技能栈的匹配度，0-100。评分时必须列出依据的是哪几篇论文 | 论文标题/摘要 + 用户画像 | 中（语义判断，需说明理由） |
| 2 | **科研活跃度** | 近 12/24 个月论文数；是否仍出现在一作/通讯位置；arXiv 更新频率。纯计数指标，最客观 | Scholar/arXiv | 高 |
| 3 | **本科生友好度** | 🟢🟡⚪ 招生信号 + 近 3 年本科生一作/署名论文数 + 组内是否有本科生。每条都要列证据 | 主页 + 论文作者单位 | 中 |
| 4 | **培养产出** | 学生一作比例、毕业生去向（深造/工业界）、组内人均顶会数。查不到去向就标"无数据" | 实验室成员页、论文署名 | 中 |
| 5 | **资源与开放度** | 是否常开源代码/模型/数据（GitHub 仓库数、commit 频率、star）；实验室规模 | GitHub + 主页 | 中高 |
| 6 | **竞争烈度** | 粗估计：学校层次 × 老师引用增长斜率 × 招生帖热度。**必须标注"粗估计"，只分 高/中/低 三档** | Scholar 引用曲线等 | 低 |
| 7 | **可达性** | 是否有公开招生渠道、邮箱可得性、地理因素（北京/成都/远程可行） | 主页 | 高 |

**指标填写原则（证据驱动硬规则）：**
1. 每个指标的每一分都必须由可溯源的事实支撑（某篇论文、某段主页原文、某个 GitHub 数据），**没有证据的指标一律填"无数据"，严禁凭印象估分、严禁用推测填补空缺**；
2. 只输出分项分 + 证据，总分仅作参考——把多维信息压成一个总分是伪精确；
3. 权重用户可调，不设死权重；
4. 分数旁边附"这个分是怎么来的"，点击可展开证据原文。

### M2｜导师深潜（针对用户点名的某位老师）

**信源优先级（v0.4 强化）：个人主页 > 实验室主页 > 学校官网 > 第三方平台。** 个人主页是老师自己维护的，更新最快、信息最真；学校官网只用来核对职称等框架信息。

- **研究轨迹时间线**：近 3-5 年论文按时间排列，标出方向漂移（例如从纯 NLP 转向 Agent/具身），这比"研究方向"四个字更能预测他下一个项目缺什么人；
- **实验室生态**：组里学生规模、毕业生去向、一作学生是谁（判断本科生有没有机会拿到一作）；
- **活跃度指标**：近 12/24 个月论文数、是否还出现在一作/通讯位置（判断是上升期还是退居管理）；
- **合作网络**：常合作的老师/机构（有时"曲线进组"比直接申请容易）；
- **工程足迹**：GitHub 组织/个人账号——star 数、commit 频率、最近开源了什么（判断组里工程文化和当前动手方向）；
- **个人主页细节挖掘**：News 板块（最近获奖/开源/演讲）、Teaching（教什么课反映他的核心能力圈）、Prospective Students 板块原文（逐字引用，这是🟢🟡⚪判定的直接证据）。

### M3｜论文深度拆解

**第 0 步：值不值得读（拆解前的 30 秒判断）**

在进入完整拆解前，先输出一张"阅读决策卡"：
- **定位**：这篇在老师工作序列里的位置——开山作 / 代表作 / 跟进作 / 边缘灌水作；
- **匹配度**：与用户兴趣方向和当前技能的相关性（高/中/低 + 一句话理由）；
- **优先级建议**：精读 / 速读 / 跳过，以及预计阅读耗时；
- **前置知识**：读这篇之前需要先懂什么（若用户档案里有缺口，直接指出补什么）。
用户确认"精读"后才进入完整拆解，避免一头扎进不重要的论文。

**完整拆解固定框架（每篇统一，便于形成阅读习惯）：**
1. **解决目标**：这篇论文到底要解决什么问题？用一句话说清"痛点"；
2. **实际背景**：这个问题在真实场景里长什么样，为什么之前的方法不够；
3. **实验设置**：数据集、基线、评价指标、算力规模；
4. **方法流程**：pipeline 逐步走一遍，配结构示意；
5. **概念解释**：按 2.2 节规则执行——原理直述、禁用比喻、档案外概念先做前置解释；
6. **结果与局限**：数字背后的含义，作者没说透的弱点；
7. **复现可行性**：若用户想复现，标注目标设备（A/B）与预估资源，跑不动就直接说。

**原文佐证硬规则（贯穿 M3/M5）：**
- 拆解中每一处"原理阐述"（这个方法是怎么工作的）必须贴出论文原文句子 + 位置标注（节/段/公式编号），先原文、后解读，二者分开排版；
- Agent 自己的观点（"我认为本文的关键创新是……""这个实验设计有缺陷……"）同样必须挂原文证据；**找不到原文支撑的观点不允许输出**；
- 原文引用保持英文原句不翻译，解读部分用中文——避免翻译过程引入失真，也方便用户回查论文。

### M4｜进组路径分析（"我要做什么才能进这个实验室"）

输出三部分：
1. **需求侧**：从老师近期论文反推——他的项目卡在哪类技能上（数据处理？评测？推理优化？某个具体领域知识？）；
2. **供给侧**：对照用户画像，列出"已具备 / 可快速补齐 / 短期补不了"三档技能清单；
3. **行动方案**：给出一个 1-3 个月可完成、**标注目标设备（A/B）且通过算力红线检查**的"敲门砖项目"建议（理想形态：复现该老师一篇论文 + 一个小的改进点，或针对其开源工作提一个有质量的 PR/issue）。

**硬约束：** 项目建议必须过"算力检查"——超出设备 B 红线的方案直接标记或替换，不允许给出"全参数微调 7B""从头预训练"这类不可执行建议；需要设备 B 完成的任务不得分配给设备 A。

### M5｜思考批改与凝练（本 Agent 的差异化核心）

**触发：** 用户读完一篇拆解后的论文，提交自己写的思考。
**流程：**
1. **事实性检查**：对照论文原文，找出知识性错误（张冠李戴的方法、记错的数字、误解的流程），逐条指出并**贴出原文句子**作为依据；
2. **偏题检测**：判断思考是否偏离论文的核心贡献（比如在细枝末节的超参上长篇大论，却没抓住方法创新的关键）；
3. **深度追问**：指出"还有哪些可以深挖但没写的角度"（延续费曼式追问：我扮演小白问你，你答不上来的地方就是盲区）；
4. **凝练输出**：把修正后的思考重写成**一段不带小标题的连贯段落**，要求突出思考深度（即：不是复述论文，而是"论文做了什么 + 我意识到什么 + 这让我想到什么"）。

**设计要点：**
- 批改遵循原文佐证硬规则：先引原文、再下判断，防止模型凭印象误判用户；
- 允许用户对批改结果申诉复核——批改者自己也可能幻觉；
- 凝练段落默认中文、学术随笔口吻，可直接用于申请邮件或面试自述；
- 每次批改的"错误记录"回流到长期知识档案（见第 5 节）。

### M6｜实时情报监测

**触发：** 用户"收藏"某位老师后自动开启（院校机会监测默认全局开启）。
**监测对象与信号：**

| 监测源 | 信号 | 频率建议 |
|---|---|---|
| 老师个人主页 | 页面内容 diff（新增招生信息、研究方向变更、Prospective Students 板块变动） | 每周 |
| GitHub（个人 + 实验室组织） | 新仓库、commit 活跃度变化、star 异常增长、新 release | 每周 |
| Scholar / arXiv | 新论文（按作者名 + 机构过滤） | 每周 |
| 学院新闻页 | 获奖、新项目、任职变动 | 每两周 |
| **目标院校官方公告**（v0.4 新增） | 研究生院/学院官网的"通知公告"栏目：夏令营、暑研、访问学生、实习招募等 | 申请季（3-7 月）每周两次，平时每周 |

**输出：** 有变动时生成"情报简报"：发生了什么变化 + 对用户意味着什么（例如"主页新增'欢迎 2026 暑期实习生'→ 申请窗口已开，建议两周内发邮件"）。
**技术要点：** 主页 diff 要做语义级比对（忽略时间戳、计数器等噪音变动），只对实质性变化告警，避免告警疲劳。

4. **时效关**：未过截止日期。

## 6. 长期知识档案（护城河，独立成节）

**定位：** Agent 相对通用工具的核心壁垒——它随时间越来越懂"用户"。

**档案内容（持久化，持续演化）：**
1. **知识水位档案**（第 2.1 节的活版本）：每篇拆解后更新——"这个概念已掌握，下次不用展开"；同时作为 2.2 节"前置概念预解释"的判定依据；
2. **错误模式库**：M5 批改中发现的知识性错误按类型归档（如"总把 RLHF 和 DPO 的训练目标混淆"），后续拆解和追问针对性补强；
3. **已读论文库**：读过的论文 + 凝练后的思考段落（申请材料的素材库）；
4. **技能 gap 清单**：M4 历次分析的汇总，标记"已补齐/待补"；
5. **目标老师清单**：收藏状态、对比记录、情报简报历史、接触进度（已读论文→已发邮件→已回复）；
6. **机会档案**：历年目标院校活动的开放时间记录——今年没赶上的，明年提前预警。

**反哺机制：** 每次会话开始，Agent 加载档案校准自己的行为——解释深度、推荐项目难度、追问方向都随档案演化。三个月后它给的建议应明显比今天更准。

## 7. 系统工作流（不写代码，先定流程）

```
用户查询（学校 / 学院 / 个人 三级输入）
  │
  ▼
[Planner] 判断意图与输入粒度：列名单？对比？深挖某老师？拆论文？批改思考？
  │
  ├── M1/M1.5/M2 路径 → [定位相关学院/单位 → 枚举全部师资 → 相关性筛选]
  │                     → [官网框架信息 → 逐人追踪个人主页（最高优先级信源）]
  │                     → [检索器：主页+Scholar+GitHub] → [抽取器：结构化卡片+职业阶段判定]
  │                     → [校验器：每条信息挂引用+置信度+🟢🟡⚪分级；查不到如实报告]
  │                     → [全景表(人数不限) → 用户勾选 → 深度对比(2-5人，证据驱动评分)]
  │
  ├── M3 路径 → [第0步：阅读决策卡] → 用户确认精读
  │           → [获取论文全文] → [按七段框架拆解：原理直述、禁比喻、
  │             前置概念按档案判定、每处阐述贴原文句子] → 输出
  │
  ├── M4 路径 → [读取用户画像 + 双硬件红线 + 老师研究轨迹] → [gap 分析]
  │           → [算力可行性检查（标注设备A/B）] → 输出行动方案
  │
  ├── M5 路径 → [用户思考 vs 论文原文逐点比对] → [错误/偏题/补充，全部挂原文]
  │           → [凝练段落] → [错误记录回流长期知识档案]
  │
  └── M6 后台 → [定时抓取：收藏老师主页/GitHub/Scholar + 目标院校公告栏]
              → [语义diff + "适用于我"四关过滤] → [情报简报 + 机会看板倒计时]
```

**关于"做两个版本"的工程决策（已确认）：**
不维护两套 Agent，采用**一套代码 + 双硬件档案**：画像里存设备 A/B 两份红线表，M4 给建议时按任务类型自动分配设备并标注。维护两个版本会导致知识档案分裂、规则双倍维护、行为不一致。如果以后要在两台机器上各跑一个实例，同步的是"档案数据"，而不是"Agent 代码"。

## 8. 审计记录（v0.1 → v0.4 变更汇总）

### v0.1 → v0.2 已吸收
1. "一一列出所有老师" → 降级为"列出 + 完整性声明"，附来源与抓取日期；
2. "目前在干什么" → 官网自述与近 12 个月论文动态分列，不合并；
3. 论文拆解 → 增加第 0 步"值不值得读"决策卡；
4. 批改模块 → 增加"引用锚点"硬要求 + 用户申诉复核机制；
5. "欢迎实习生" → 🟢🟡⚪ 三级分类，⚪ 严禁说成 🟢；
6. 新增 M1.5 对比视图、M6 实时监测、长期知识档案独立成节、申请时间线提醒；
7. 双硬件配置档案 + 双机分工策略；明确"不做两套 Agent"。

### v0.2 → v0.3 已吸收
8. **解释风格硬规则**：原理直述、禁用生活比喻；复杂概念按用户档案判定后前置解释；
9. **M1 输入泛化**：支持学校/学院/个人三级输入；粗输入时"先枚举全部师资、再按证据筛选排序、低相关的折叠展示"；查不到名单如实报告，绝不凑数；
10. **指标证据驱动硬规则**：对比视图每一分必须挂可溯源事实，无证据填"无数据"，严禁凭印象估分；
11. **原文佐证硬规则**：论文拆解与批改中，一切原理阐述和 Agent 观点必须贴原文句子（英文原句+位置标注），先原文后解读；找不到原文支撑的观点不允许输出。

### v0.3 → v0.4 已吸收
12. **M1.5 两档模式**：全景对比表（人数不限、低成本客观指标、粗筛用）→ 用户勾选 2-5 人进入深度对比（完整七指标+证据链）；
13. **M1 新增"职业阶段"字段**：青年/中年/资深判定（依据学位年份、职称、履历，证据不足标"无法判定"）+ 面向申请者实际含义的一句话简评（标注"经验性判断"）；
14. **"官网 → 个人主页"两级联动硬规则**：个人主页为最高优先级信源；官网仅核对框架信息；无个人主页显式标注；
15. **申请时间线升级为"院校机会监测与倒计时"**：直接监测目标 985/211 官网公告栏，"适用于我"四关过滤（对象/方向/门槛/时效），机会看板统一输出"距离 X 月 X 日还有 N 天"倒计时 + 行动项 + 状态分级。

### 保留意见
16. 套磁邮件草稿功能暂缓——M5 凝练段落可直接复用为邮件素材，待 MVP 跑通后再决定是否独立成模块。

## 9. 分阶段实施路线（建议）

- **MVP（先做透）：** M1（三级输入 + 名单枚举 + 官网/主页两级联动 + 卡片含职业阶段与🟢🟡⚪分级）→ M3（第0步 + 七段拆解 + 原文佐证）→ M5（批改凝练 + 错误记录）。这条链路是"读论文-写思考-被纠正"的学习闭环，也是用户当下最刚需的部分。
- **v1：** M2 深潜 + M4 匹配分析（双硬件算力检查）+ M1.5 两档对比。
- **v2：** M6 监测 + 院校机会看板与倒计时 + 知识档案完整演化。
- **不做（明确划界）：** 不自动发邮件、不替用户做申请决策、不抓取需要登录的平台数据、不输出无来源断言、不维护两套 Agent 代码、不用生活比喻解释概念。
